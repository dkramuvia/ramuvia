# 문자 인증 — 알리고 붙이기 (2026-09-30)

<https://smartsms.aligo.in>

문자 인증(가입·새 기기 로그인)과 긴급 문자를 알리고로 보냅니다.

---

## 0. 발신번호는 누구 번호로?

사용자가 받는 문자의 **발신자로 찍히는 번호**입니다. 되묻는 전화도 그 번호로 옵니다.
개발 중에는 담당자 개인 번호로 두어도 되지만, **실제 서비스에서는 회사 대표번호가 맞습니다.**
바꾸려면 그 번호도 따로 사전등록해야 하므로 미리 정해 두는 편이 좋습니다.
**대표님 확인이 필요합니다.**

## 1. 값 두 개를 어디에 넣는가

**`ramupin-server/.env` 에만 넣습니다.** 앱에는 넣지 않습니다.

```
SMS_PROVIDER=aligo
ALIGO_USER_ID=<알리고 아이디 (Identifier)>
ALIGO_API_KEY=<발급키>
ALIGO_SENDER=<알리고에 사전 등록한 발신번호, 숫자만>
ALIGO_TEST_MODE=Y
ALIGO_ALLOW_NUMBERS=<개발 중에 문자를 받을 내 번호>
```

| 알리고 화면의 이름 | 우리 이름 |
|---|---|
| Identifier · 아이디 | `ALIGO_USER_ID` |
| 발급키 · API Key | `ALIGO_API_KEY` |

> **발급키를 앱에 넣으면 안 됩니다.** 앱은 누구나 뜯어볼 수 있어서, 앱에 들어간 키는
> 공개된 키입니다. 남이 그 키로 문자를 보내고 **요금은 우리가 냅니다.**
> 그래서 앱은 "이 번호로 인증번호 보내줘" 만 서버에 부탁하고,
> 번호 확인·횟수 제한·발송은 모두 서버가 합니다.

`.env` 는 `.gitignore` 에 들어 있어 저장소에 올라가지 않습니다.
값을 바꾸면 **서버를 다시 띄워야** 적용됩니다.

## 2. 넣기 전에 알리고에서 할 일

- [ ] **발신번호 사전등록** — 전기통신사업법상 등록·인증된 번호로만 보낼 수 있습니다
      (발신번호 도용을 막는 제도라 업체가 예외를 두지 않습니다).
      등록 안 된 번호로 보내면 `등록/인증되지 않은 발신번호입니다.` 로 거절되고,
      **건수는 차감되지 않습니다.**
      - **문자 API 담당자 등록과는 다른 메뉴입니다.** 담당자는 포인트 부족 알림을 받는 사람일 뿐,
        그 번호가 발신번호가 되지는 않습니다 (2026-09-30 에 이걸로 한 번 헛돌았습니다)
      - 본인 명의 **휴대폰이면 본인인증으로 즉시** 됩니다 (서류 없이)
      - 그 밖에는 **통신서비스 이용증명원**(1개월 내 발급) + 사업자등록증 + 재직증명서가 필요하고,
        승인까지 **영업일 최대 3일**
      - 증명원 이름이 통신사마다 다릅니다 — KT 원부증명서 · SKT 이용계약 등록사항 증명서 · LG U+ 가입 사실 확인서
- [ ] **발송 가능 IP 등록** — 알리고는 등록한 IP 에서만 API 를 받아 줍니다.
      개발할 때는 **개발 PC 의 공인 IP**, 나중에는 **서버 IP** 를 등록해야 합니다.
      `node scripts/check-sms.mjs` 가 지금 IP 를 알려 줍니다.
      인터넷 회선이 바뀌면 IP 도 바뀌어 다시 막힐 수 있습니다
- [ ] **건수 충전** — 남은 건수가 0이면 보내지지 않습니다
- [ ] 발급키 확인 (관리자 > 문자 API > 인증키 관리)

### 오류 메시지 읽는 법

직접 찔러 보고 알아낸 뜻입니다. 말이 거의 같아서 헷갈립니다.

| 응답 | 뜻 |
|---|---|
| `-101` `인증오류입니다.` | 그런 **아이디가 없습니다** |
| `-101` `인증오류입니다.-IP` | 아이디·키는 **맞고**, 보내는 **IP 가 등록되지 않았습니다** |
| `-102` `API 인증오류입니다.` | 계정은 있는데 문자 API 를 쓸 수 없는 상태 |
| `-101` `API 키가 입력되지 않았습니다.` | `ALIGO_API_KEY` 가 비었습니다 |

`check-sms.mjs` 가 이 구분을 대신 해서 어디를 볼지 찍어 줍니다.

## 3. 넣고 나서 확인

```
cd ramupin-server
node scripts/check-sms.mjs                  # 키가 맞는지·남은 건수 (문자 안 감)
node scripts/check-sms.mjs --send           # ALIGO_ALLOW_NUMBERS 의 첫 번호로 (모드는 .env 따라)
node scripts/check-sms.mjs --send --real    # .env 를 안 고치고 이번 한 번만 진짜로
```

거절당하면 **건수가 차감되지 않습니다.** 발신번호 미등록으로 막혔을 때 확인했습니다.

**번호는 `.env` 에만 적습니다.** 명령줄에 적으면 셸 기록과 화면에 남고,
그 화면을 남에게 보여 주게 됩니다.

`ALIGO_TEST_MODE=Y` 인 동안은 **요금이 나가지 않고 문자도 오지 않습니다.**
나머지 동작(키 확인·발신번호 확인)은 실제와 같으므로, 먼저 `Y` 로 확인하고
문자를 실제로 받아 볼 때 `N` 으로 바꿉니다.

## 3-1. 개발 중에는 적어 둔 번호로만 나갑니다

씨드 계정 7개에는 **지어낸 번호**가 들어 있습니다. 운영이 아닌 곳에서 `aligo` 를 켜면
확인 스크립트가 그 번호로 **실제 문자를 보냅니다.** 지어낸 번호는 모르는 사람의 번호일 수
있고 요금도 나갑니다. 그래서 `ALIGO_ALLOW_NUMBERS` 에 적은 번호로만 나가게 했습니다.

- 비워 두면 **서버가 시작을 거부합니다** (비면 "아무 번호나 허용" 이 되어 버리므로)
- 목록에 없는 번호로 보내려 하면 **오류를 던집니다.** 조용히 넘기면 "왜 안 왔지" 를 한참 찾게 됩니다
- `NODE_ENV=production` 에서는 이 제한이 없습니다

### 확인 스크립트를 돌릴 때는 `dev` 로 두세요

`scripts/dev-login.mjs` 가 개발용 인증번호 **123456** 으로 로그인합니다
(`SMS_PROVIDER=dev` 일 때만 그 번호가 통합니다). 그래서 13개 확인 스크립트를 돌릴 때는
`SMS_PROVIDER=dev` 여야 합니다. **문자를 실제로 받아 볼 때만 `aligo` 로 바꾸고 되돌립니다.**

## 4. 어떻게 동작하는가

```
앱  ──"01012345678로 인증번호 보내줘"──▶  서버
                                        인증번호 6자리 생성 (3분)
                                        번호는 해시+암호화해서 저장
                                        ──▶ 알리고 ──▶ 사용자 문자
앱  ──"123456"──▶ 서버가 맞는지 확인
```

- 코드: `ramupin-server/src/auth/sms.service.ts` (`SmsService.send()`)
- 설정: `ramupin-server/src/config/env.ts`
- `SMS_PROVIDER=dev` 면 실제로 보내지 않고 서버 로그에만 찍히고, **인증번호는 123456 고정**입니다.
  개발할 때 문자 요금을 쓰지 않으려고 둔 것입니다. 운영에서는 `dev` 면 서버가 뜨지 않습니다.
- `SMS_PROVIDER=aligo` 인데 세 값 중 하나라도 비어 있으면 **서버가 시작할 때 막습니다.**
  이렇게 하지 않으면 인증번호가 조용히 안 가고, 사용자는 "문자가 안 와요" 만 겪게 됩니다.

## 5. 실패할 때 어디를 보는가

서버 로그에 `문자 발송 거절 ... [코드] 이유` 가 남습니다.
**번호 원문과 발급키는 로그에 남기지 않습니다** (번호는 `010-****-5678` 로 가립니다).
로그는 여러 사람이 보고 오래 남기 때문입니다.

| 응답 메시지 | 뜻 |
|---|---|
| `등록/인증되지 않은 발신번호입니다.` | `ALIGO_SENDER` 를 알리고에 **사전등록**하지 않았습니다 |
| `인증오류입니다.-IP` | 보내는 IP 가 등록되지 않았습니다 (2장) |
| 잔액·건수 부족 | 충전이 필요합니다 |

`check-sms.mjs` 가 이 메시지들을 읽어 어디를 볼지 찍어 줍니다.
