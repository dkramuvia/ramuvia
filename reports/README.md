## 만드는 순서

1. 직전 보고서를 복사해 `YYYY-MM-DD.md` 로 새로 만들고 내용을 고칩니다. 앱 화면 캡처는 `images/YYYY-MM-DD/` 에 넣습니다.
2. Word 파일 만들기:
   ```bash
   cd reports
   npm install        # 처음 한 번
   node build.mjs 2026-09-28
   ```
   → `out/라무핀_진행보고_2026-09-28.docx` (out 폴더는 git 에 올리지 않음)
3. 소스 공유: 커밋 → 보고일 태그 → GitHub push
   ```bash
   git tag report-2026-09-28
   git push origin main --tags
   ```
   `.env` 같은 비밀값이 커밋에 없는지 먼저 확인합니다.

## 작성 원칙

- 읽는 사람은 대표님(비개발자): 기술 용어 대신 "무엇이 되는지"로 씁니다.
- 순서: 한눈에 보기 → 전체 일정 → 한 일(캡처 포함) → 다음 계획 → 요청 사항(담당·기한) → 위험 → 소스 공유
- 표의 상태 칸은 `완료 / 진행 / 예정 / 대기 / 주의 / 지연 / 정상` 중 하나로 쓰면 색이 입혀집니다.
