# 위치 데이터 보관 방식 재요청

2026-09-22 · 라무핀 개발팀

> **9월 17일에 같은 내용을 드렸으나 아직 답을 받지 못했습니다.**
> 그 사이 **100만 대 이상**을 보신다는 말씀을 들어, 그 기준으로 숫자를 다시 계산했습니다.
> **결정이 필요한 것은 두 가지**이고, 둘 다 **법무 확인**이 필요해 보입니다.

## 1. 왜 다시 드리나

위치를 어떻게 보관할지는 **한번 정하면 되돌리기 어렵습니다.** 데이터가 쌓인 뒤에 바꾸려면 그동안 모은 것을 전부 다시 처리해야 하고, 이미 지운 것은 되살릴 수 없습니다.

지금은 시험용 데이터뿐이라 **바꾸기 가장 쉬운 시점**입니다.

100만 대를 보신다면 이 결정이 **서버 비용을 15배 가르는** 항목입니다.

| 시점 | 바꾸는 난이도 |
|---|---|
| 지금 (시험 데이터만) | 쉬움 |
| 출시 직후 | 가능하지만 과거 데이터 전부 재처리 |
| 6개월 운영 후 | **사실상 불가** |

---

## 2. 질문 1 — 보관 기간 6개월이 맞습니까?

WBS에는 **"서버 위치·이동 경로는 6개월 후 파기"**로 되어 있습니다.

그런데 **위치정보법에는 위치정보 이용·제공 사실 확인자료를 보관할 의무**가 따로 있습니다. 이 둘이 서로 맞는지 확인이 필요합니다.

| 답 | 결과 |
|---|---|
| 6개월이 맞다 | 지금 설계 그대로 진행합니다 |
| 더 길어야 한다 | 저장량이 비례해서 늘어납니다 (1년이면 2배) |
| 더 짧아도 된다 | 비용이 그만큼 줄어듭니다 |

## 3. 질문 2 — 몇 달 전의 1분 단위 기록이 필요합니까?

이것이 핵심입니다. 두 가지 보관 방법 중 하나를 고르는 기준이 됩니다.

**가. 찍은 것을 전부 보관** — 지금 방식입니다. 9시 00분, 9시 01분, 9시 02분... 을 전부 남깁니다.

**나. 머문 곳으로 정리해서 보관** — 아래처럼 남깁니다.

- 09:00 ~ 13:00 자택에 4시간 머묾
- 13:00 ~ 13:40 이동 (자택 → 회사)
- 13:40 ~ 18:00 회사에 4시간 20분 머묾

단, **최근 7일은 찍은 그대로** 둡니다. 어제 일은 1분 단위로 다 보이고, 석 달 전 일만 이렇게 정리됩니다.

### 판단 기준

**몇 달 지난 일로 법적 분쟁이 생겼을 때, 분 단위 기록을 증거로 제출할 일이 있는가.**

| 상황 | 필요한 기록 |
|---|---|
| 어제 아이가 어디 갔었나 | 최근 7일 원본으로 충분 |
| 지난달 어느 병원에 갔었나 | 요약으로 충분 ("그날 ○○병원에 2시간") |
| 3개월 전 교통사고 시각의 정확한 위치 | **원본 필요** |
| 3개월 전 실종 시점의 분 단위 동선 | **원본 필요** |

## 4. 판단에 필요한 사실

### 4-1. 저장한 것의 대부분은 같은 이야기의 반복입니다

9월 17일, 휴대폰을 책상에 4시간 올려 두고 실제로 재 봤습니다.

| | 결과 |
|---|---|
| 모인 위치 | 270건 |
| 서로 다른 좌표 | **4개** (약 2m 안에서 흔들린 것) |

270건을 저장했지만 실제 정보는 **"4시간 동안 이 자리에 있었다" 한 줄**입니다.

### 4-2. 비용 차이 (6개월 보관 기준)

| | 10만 대 | 100만 대 |
|---|---|---|
| **가. 전부 보관** | 5.9 TB / 월 785달러 | **58.9 TB / 월 7,845달러** |
| **나. 요약 보관** | 0.4 TB / 월 51달러 | **3.9 TB / 월 515달러** |
| 차이 | 15배 | 15배 |

금액은 저장 공간값만입니다. 데이터가 많을수록 더 크고 비싼 데이터베이스가 필요하므로 전체 서버 비용 차이는 이보다 더 벌어집니다.

> **100만 대에서 58.9TB는 데이터베이스 한 대가 담을 수 있는 최대치(64TB)에 거의 닿습니다.**
> 전부 보관으로 가면 서버를 여러 대로 쪼개는 작업이 추가로 필요합니다.

### 4-3. 요약해도 잃지 않는 것 / 잃는 것

| | 가. 전부 보관 | 나. 요약 보관 |
|---|---|---|
| 최근 일주일 이동 경로 | 1분 단위로 다 보임 | 똑같이 다 보임 |
| 석 달 전 "그날 어디 있었나" | 보임 | 보임 |
| 석 달 전 **1분 단위** 세밀한 움직임 | 보임 | **사라짐** |
| 이상징후 판정 (12·24·48시간) | 됨 | 똑같이 됨 |
| SOS 기록 | 남음 | 남음 (아래 참고) |

### 4-4. 요약하지 않고 원본 그대로 영구 보관하는 구간

사고나 분쟁의 근거가 되는 기록은 뭉치지 않습니다.

| 구간 | 처리 |
|---|---|
| SOS를 누른 순간 | 원본 영구 보관 |
| **SOS 전후 30분** | 원본 영구 보관 — 누르기 **전**에 무슨 일이 있었는지가 더 중요합니다 |
| 이상징후가 잡힌 구간 | 원본 보관 |
| 안심장소 진입·이탈 | 원본 보관 (알림을 보낸 근거) |

그리고 아무리 오래 같은 곳에 계셔도 **하루 단위로는 끊어서 남깁니다.** 집에만 계신 분을 "한 달 내내 집" 한 줄로 뭉치면 **"어제 살아 계셨나"를 확인할 근거가 없어지기** 때문입니다.

## 5. 개발팀 의견

**"나. 요약 보관"을 권합니다.** 다만 조건이 있습니다.

1. **최근 7일은 원본 그대로** — 실제로 쓰는 기간은 거의 다 여기입니다
2. **SOS·이상징후 구간은 영구 보관** — 사고 근거가 되는 기록
3. **하루 한 줄은 반드시 남김** — 생존 확인 근거

이렇게 하면 실질적으로 잃는 것이 거의 없으면서 서버 비용이 15분의 1이 됩니다.

다만 **"법적 분쟁 시 증거력"은 개발팀이 판단할 수 있는 영역이 아닙니다.** 법무 의견을 받아 주시면 그에 맞춰 만들겠습니다.

## 6. 언제까지 답을 주시면 되나

지금은 "가(전부 보관)" 방식으로 동작하고 있어 **당장 문제는 없습니다.**

**11-27 중간 시연 전까지 방향만 정해 주시면 충분합니다.**
