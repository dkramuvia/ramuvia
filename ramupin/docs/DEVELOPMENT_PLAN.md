## 2. 개발 순서

핵심 원칙: **결정 확정 → 설정값 구조 → 화면(목업) + GPS PoC → 기기 기능 → 서버 연동 → 백그라운드·비상 → 결제·광고 → 부가 기능 → QA**

API 주소나 키 같은 연동 정보는 **5단계에서 넣습니다.** 그 전까지는 `src/api/mock`으로 개발하므로 서버 일정이 늦어져도 앱 개발이 멈추지 않아요.
괄호 안 숫자는 WBS 항목 번호입니다.

app/                      # 화면 라우트 (expo-router, 파일 = 화면)

  (app)/(tabs)/map | people | gallery

src/
  api/                    # 서버 통신
    client.ts             # axios 인스턴스, 토큰, 에러 처리
    endpoints/            # 도메인별 API 함수 (auth, friends, location, policy ...)
    mock/                 # 목업 데이터 (USE_MOCK=true일 때 사용)
  config/env.ts           # ★ API 주소, 키 등 연동 정보가 모이는 곳
  components/ui/          # 공통 컴포넌트
  db/                     # (추가 예정) 로컬 SQLite: 이동 경로, 알림 보관함, 채팅
  features/               # 도메인별 로직/컴포넌트
    policy/               # (추가 예정) 플랜 정책, usePlan / limit 헬퍼
    location/             # (추가 예정) 수집, 적응형 주기, 전송 큐
    map/                  # (추가 예정) 지도 추상화 (OS / Naver / Mapbox)
    sharing/  sos/  geofence/  emergency/ ...
  i18n/                   # 다국어 (ko.json, en.json)
  stores/                 # 전역 상태 (zustand)
  theme/                  # 색상, 폰트, 간격
  types/                  # 공용 타입
modules/                  # (추가 예정) Expo 네이티브 모듈: GPS·GNSS·활동 인식
docs/                     # 기획 분석, 개발 계획, WBS 대조
.env.example              # 환경변수 목록 (실제 값은 .env, git 제외)
