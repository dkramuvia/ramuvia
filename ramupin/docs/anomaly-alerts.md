## 1. 한 장 요약

"전화기가 꺼졌다 / 한 자리에서 안 움직인다 / 신호가 끊겼다"를 **시간이 지날수록 단계를 올려 가며** 알리는 기능입니다.

- 판단 축 3가지: **배터리**, **GPS 고정**, **신호 두절**
- 대상 2가지: **일반**(친구에게 알림) / **1인단독**(모니터링 사이트에 표시, 친구에게는 안 보냄)
- 두 축이 겹치면 더 위험: `GPS 고정 + 배터리 0%`가 최우선 위험군

### 핵심: 이 판단은 **서버가** 합니다

폰이 꺼지면 앱은 아무것도 못 합니다. "48시간 무응답"은 앱이 알 수 없어요.
그래서 **서버가 주기적으로 모든 사용자의 마지막 상태를 훑어서** 알림을 만들어야 합니다 (WBS 2.5·9.4와 같은 방향).
앱이 하는 일은 두 가지뿐입니다: ① 상태를 꼬박꼬박 보내기 ② 받은 알림을 보여 주기.

## 2. 알림 단계표

시간 값은 **모두 서버 정책값**입니다. 앱·서버 코드에 숫자를 넣지 않습니다 (WBS 2.1).

### A·B. 배터리 트랙

| 조건 | 일반 → 친구 | 1인단독 → 모니터링 | 회사 조치 (사람이 함) |
|---|---|---|---|
| 배터리 ≤ 10% | "OOO님의 배터리가 부족합니다" | - | 없음 |
| 배터리 = 0% (방금) | "전화기가 꺼졌습니다" | - | 관찰 시작 |
| 0% 지속 3h | "확인 바랍니다" | - | 관찰 |
| 0% 지속 12h | "확인 바랍니다" | 표시 | 1인단독은 회사가 전화 (1차) |
| 0% 지속 24h | "확인 바랍니다" | 표시 | 전화 재시도 + 가족 통보 |
| 0% 지속 48h | "확인 바랍니다" | 표시 (최우선) | 전화 → 실패 시 경찰·소방 공동대응 |

### C·D. GPS 고정 트랙

| 조건 | 일반 → 친구 | 1인단독 → 모니터링 |
|---|---|---|
| 12h 고정 | "위치가 12시간 고정되었습니다" | 통보 (앱 푸시로 "괜찮으신가요?" 응답 요청) |
| 24h 고정 | "24시간 고정되었습니다" | 통보 (확인콜) |
| 48h 고정 | "48시간 고정되었습니다" | 통보 (현장 출동 검토) |

> 일반 사용자도 48h에서는 모니터링 사이트에 **참고 표시**가 뜹니다.

> **GPS 고정 판정 기준 (확정)**: 반경 **50m** 안에 연속으로 머물면 "고정". 실내 GPS 오차가 100m까지 벌어져서
> 그보다 작은 기준을 쓰면 가만히 있어도 "움직였다"로 잘못 보게 됩니다 (09-17 실측).

### E·F. GPS 고정 + 배터리 0% (최우선 위험군)

한 자리에서 못 움직이는데 배터리까지 꺼진 상태 = 낙상·기절 가능성.
**단독 트랙보다 단계를 앞당깁니다.**

| 조건 | 일반 | 1인단독 |
|---|---|---|
| 12h | 친구에게 "친구의 안전을 확인하세요", 감시목록 즉시 등록 | 대기 없이 **즉시 확인콜** |
| 24h | + 관제 참고 통보 | 확인콜 재시도 + 비상연락망 |
| 48h | 관제 확인콜 → 경찰 공동대응 | **즉시 출동, 112/119 공동대응** |

### G·H. GPS 고정 + 배터리 100% (충전 중)

집에서 충전기 꽂아 둔 정상 상황일 가능성이 높지만 배제하지 않습니다.
일반은 48h에서 관제 참고 통보, 1인단독은 12h부터 관제 통보.

### I·J. 신호 두절 (마지막 배터리 100~20%)

자연 방전으로 설명이 안 되는 두절이라 **배터리 0% 트랙보다 더 이른 단계에서 개입**합니다.

| 조건 | 일반 | 1인단독 |
|---|---|---|
| 30분~1h | 친구에게 "위치 신호가 확인되지 않습니다" | 모니터링 표시 시작 |
| 3h | 친구 알림, 관찰 | **즉시 확인콜** |
| 12h | 친구 알림, 감시목록 등록 | 확인콜 재시도 + 가족 통보 |
| 24h | + 관제 참고 통보 | 비상연락망 전원 가동, 출동 검토 |
| 48h | 관제 확인콜 → 경찰 공동대응 | **즉시 출동, 112/119 공동대응 (전체 중 최우선)** |

## 3. 지금과 무엇이 다른가

| 항목 | 현재 상태 | 필요한 것 |
|---|---|---|
| 배터리 알림 | 10% 1회 (WBS 9.1) | 0% 지속 시간 단계 5개 추가 |
| GPS 고정 감지 | **없음** | 체류 판정(WBS 4.9 30분)과 별개로 12/24/48h 고정 판정 |
| 신호 두절 감지 | **없음** | 마지막 수신 시각 기준 5단계 |
| 충전 중 여부 | **앱이 안 보냄** | 배터리 상태(충전/방전)를 위치와 함께 전송 |
| 1인단독 구분 | 친구가 없으면 회사 계정(RamuVia)이 친구 (WBS 4) | 알림 대상이 **친구가 아니라 모니터링 사이트**로 갈라짐 |
| 모니터링 사이트 | **없음** | 이상징후 목록·사용자 상세 화면과 데이터 (전화는 회사가 직접) |
| 알림 중복 방지 | 없음 | 같은 단계는 한 번만 (단계별 발송 이력) |

## 5. 확정된 사항 (09-17 대표 확인)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 관제센터 범위 | **모니터링 사이트에 표시하는 것까지가 개발 범위.** 표시된 건은 **회사가 대신 전화**합니다. 확인콜·출동은 사람이 하는 일이라 시스템에 넣지 않고, 24시간 관제 인력 운영 계획도 필요 없습니다 |
| 2 | GPS 고정 판정 | **반경 50m 안에 연속 12시간** (실내 GPS 오차 100m 실측 반영). 24h·48h도 같은 반경 |
| 3 | 야간 처리 | **야간 제외 규칙을 두지 않습니다.** 밤에도 시간이 그대로 쌓입니다 |
| 4 | 1인단독 위치 제공 동의 | 별도 고지·동의 절차를 만들지 않습니다 (회사 판단) |
| 5 | 신호 두절인데 마지막 배터리가 낮을 때 | **20% 미만에서 끊겼으면 배터리 트랙으로 보냅니다.** 자연 방전으로 설명이 되기 때문에 신호 두절(최우선 위험군)로 올리지 않습니다 |
| 6 | 알림 해제 | 사용자가 **다시 움직이거나 전화기를 켜면 모니터링 목록에서 자동으로 빠집니다.** 단, 언제 발생해서 언제 풀렸는지는 기록으로 남깁니다 |

> 3번 결과: 밤 11시에 잠들면 다음 날 오전 11시에 "12시간 고정" 알림이 갑니다. 매일 반복될 수 있습니다.
> 운영하면서 알림이 너무 잦으면 기준 시간(정책값)을 늘리는 쪽으로 조정합니다.

### 트랙을 고르는 순서 (5번 결정 반영)

신호가 끊겼을 때 어느 트랙으로 보낼지는 **마지막으로 받은 배터리 값**으로 정합니다.

| 마지막 배터리 | 보내는 트랙 | 이유 |
|---|---|---|
| 20% 이상 | **신호 두절 (I·J)** | 자연 방전으로 설명 불가 → 강제 종료·기기 이상·분실 의심, 더 이른 단계에서 개입 |
| 20% 미만 | **배터리 (A·B)** | 그냥 방전됐을 가능성이 큼 |

### 해제 (6번 결정)

- 위치가 다시 들어오거나(신호 두절 해제), 반경 50m 밖으로 움직이거나(고정 해제), 배터리가 0%를 벗어나면 **자동 해제**
- 해제해도 `anomaly_events` 기록은 지우지 않습니다. 언제 발생해 언제 풀렸는지 남겨야 나중에 확인할 수 있습니다
- 해제 뒤 같은 상황이 다시 생기면 **1단계부터 다시** 셉니다

## 6. 아직 해결 못한 구멍: 집에만 계신 분 (09-17 발견)

### 무엇이 문제인가

거동이 불편해 **한 달 내내 집에 계신 분**을 지금 규칙에 넣으면 이렇게 됩니다.

- 12시간 고정 → 알림
- 24시간 고정 → 알림
- 48시간 고정 → 모니터링 사이트에 표시, 회사가 전화
- **안 움직이니까 자동 해제도 안 됩니다.** 한 달 내내 목록에 떠 있습니다

이런 분이 100명이면 모니터링 목록이 그분들로 꽉 차서, **정작 진짜 위험한 건을 못 봅니다.**
회사는 매일 같은 분께 전화하게 됩니다.

**더 심각한 것**: 이분들이 바로 이 앱의 핵심 사용자(노인·1인단독)입니다.
이상징후 기능이 지키려는 그 대상에게 기능이 무용지물입니다.

원본 시나리오 37개 어디에도 이 경우에 대한 예외가 없습니다.

### 왜 생기나

**위치만으로는 이 두 경우를 구분할 수 없습니다.**

| 상황 | 위치 | 활동 인식 | 실제 |
|---|---|---|---|
| 집에서 평소처럼 지내심 | 고정 | 하루에 여러 번 `walking` | 정상 |
| 집에서 쓰러져 계심 | 고정 | 계속 `still` | **위험** |

좌표는 둘 다 똑같습니다. 화장실 가고 밥 먹는 움직임은 GPS로 안 잡힙니다.

### 제안하는 규칙

1. **등록된 집(안심장소) 안에서의 위치 고정은 이상징후로 보지 않습니다.** 집에 있는 건 정상입니다
2. 대신 **"몇 시간 동안 전혀 안 움직였는지"**로 판정합니다 — 어제 붙인 활동 인식(`still` 연속 지속 시간) 기준
3. 집 밖에서의 위치 고정은 지금 규칙 그대로 (길에서 12시간 안 움직이면 위험)

제안 기준: **집 안에서 활동 인식이 6시간 연속 `still`이면 1단계.** 수면을 고려한 값이라 조정이 필요합니다.

### 확정이 필요합니다

> **집에만 계신 분의 "위치 고정"을 이상징후로 볼 것인가?**
> 안 본다면, 대신 "몇 시간 안 움직이면 위험"으로 볼지 (제안: 활동 인식 기준 6시간)

이건 요구사항 자체의 구멍이라, **원본 시나리오를 만드신 분께도 확인이 필요합니다.**

### 구현 상태

- 활동 인식(`activity` 컬럼)은 09-17 구현 완료 — 판정에 쓸 재료는 준비됨
- **안심장소 예외와 무움직임 판정은 아직 미구현**. 위 규칙이 확정되면 붙입니다
