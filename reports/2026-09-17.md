# 위치 데이터 보관 방식 결정 요청

2026-09-17 · 라무핀 개발팀

> **요약**: 위치를 "찍은 그대로 전부" 보관하는 지금 방식은 사용자가 늘면 서버 비용이 빠르게 커집니다.
> 다른 가족 위치 앱들이 쓰는 방식으로 바꾸면 **같은 정보를 담으면서 비용이 절반**이 됩니다.
> 앱 수정은 거의 없고 서버 작업 약 1주입니다. **나중에 정하면 이미 쌓인 데이터를 다시 정리해야 하므로 지금 결정하는 것이 좋습니다.**

## 1. 무엇이 문제인가

휴대폰을 책상에 4시간 올려두고 실제로 측정했습니다.

- 위치를 **270번** 확인해서 **270건**을 저장했습니다
- 그런데 실제로 기록된 장소는 **4곳**뿐이었습니다 (서로 2미터 거리)

같은 자리를 266번 다시 적은 셈입니다.

사람은 하루의 대부분을 한자리에 있습니다. 회사에 8시간, 집에 10시간. 그동안 위치는 바뀌지 않는데 지금 방식은 그 시간 내내 같은 좌표를 계속 저장합니다.

거동이 불편해 집에만 계신 분은 더합니다. 한 달이면 약 24,000건이 쌓이는데 전부 같은 좌표입니다.

## 2. 다른 회사들은 어떻게 하나

가족 위치 공유 앱(Life360 등)과 이 분야의 일반적인 방식을 조사했습니다.

| 항목 | 업계 방식 | 라무핀 현재 |
|---|---|---|
| 위치 확인 간격 | 움직이면 자주, 가만히 있으면 드물게 | 09-17 같은 방식으로 변경 |
| 걷는지 차를 탔는지 구분 | 휴대폰 센서로 판별 | 09-17 기능 추가 |
| 실내에서 Wi-Fi 활용 | 사용자에게 "Wi-Fi 켜두세요" 안내 | 기능은 되나 안내 없음 |
| **보관 방식** | **"머문 곳"으로 정리해서 보관** | **찍은 것 전부 보관** |

앞의 세 가지는 이미 맞췄습니다. **마지막 하나가 남았고, 이것이 비용에서 가장 큰 차이를 만듭니다.**

## 3. "머문 곳으로 정리한다"는 뜻

지금은 이렇게 저장됩니다.

- 09:00 가산동 사무실 / 09:03 가산동 사무실 / 09:06 가산동 사무실 … 8시간 동안 160번 반복

정리하면 이렇게 됩니다.

- **09:00 ~ 17:00 가산동 사무실에 머무름** (1건)

160건이 1건이 됩니다. 보호자가 보는 화면은 달라지지 않습니다. 오히려 "8시간 머물렀다"가 한눈에 보여 더 낫습니다.

이동 중에는 지금처럼 촘촘히 기록합니다. 경로는 실제로 계속 바뀌기 때문입니다.

> **반드시 지켜야 할 조건**: 아무리 오래 같은 곳에 있어도 **하루 단위로는 끊어서** 기록해야 합니다.
> 집에만 계신 분을 "한 달 내내 집" 1건으로 뭉치면 "어제 살아 계셨나"를 확인할 근거가 사라집니다.

## 4. 비용이 얼마나 줄어드나

기기 10만 대, 위치 6개월 보관 기준입니다.

| 단계 | 조치 | 월 서버 비용 | 필요한 작업 |
|---|---|---|---|
| 지금 | - | 약 $1,400 | - |
| 1단계 | 전송을 묶어서 보내기 | 약 $1,150 | 앱 반나절 |
| **2단계** | **머문 곳으로 정리해 보관** | **약 $700** | 서버 약 1주 |

**절반으로 줄어듭니다.** 연간으로 보면 약 1,100만 원 차이입니다.

1단계(전송 묶기)는 **기능이 전혀 바뀌지 않는 개선**이라 대표님 결정 없이 진행 가능합니다. 위치를 확인할 때마다 서버로 보내던 것을 모아서 보내는 것뿐입니다.

2단계가 이 문서의 결정 요청 사항입니다.

> 위 금액은 AWS 공개 단가로 계산한 추정치입니다. 실제 계약 단가와 사용 패턴에 따라 달라지므로 발주 전 재확인이 필요합니다.

## 5. 잃는 것은 없나

**최근 7일은 지금처럼 원본을 그대로 둡니다.** 이 경우 실질적인 손실이 없습니다.

- 최근 며칠의 상세한 이동 경로 — 그대로 볼 수 있습니다
- 몇 달 전 기록 — "그날 어디에 있었다"는 남습니다. 다만 **1분 단위의 미세한 움직임은 사라집니다**

몇 달 전의 1분 단위 기록이 필요한 경우가 있을지가 판단 기준입니다. 사고나 분쟁이 생겼을 때 근거로 써야 한다면 원본 보관 기간을 법무와 상의해 정해야 합니다.

## 6. 결정해 주실 것

1. **머문 곳으로 정리해 보관하는 방식으로 갈까요?**
2. **원본은 며칠까지 남길까요?** (제안: 7일. 30일로 하면 비용이 약 4배)
3. **위치 기록을 법적 근거로 써야 할 일이 있나요?** (있다면 법무 확인 필요)

## 7. 함께 보고드릴 사항 두 가지

### 7-1. 서버가 위치를 받는 구조를 한 번 바꿔야 합니다

보관 방식과 무관합니다. 지금은 앱이 보낸 위치를 서버가 **곧바로 데이터베이스에 씁니다.** 사용자가 많아지면 이 방식으로는 감당이 안 됩니다. 중간에 **대기열**을 두고 모아서 저장하는 구조가 필요합니다.

서버 구성안에도 이미 들어 있는 내용이라 계획을 벗어나지는 않습니다. **서버 담당자와 협의가 필요합니다.**

### 7-2. 이상징후 알림 규칙에 구멍을 발견했습니다

지난번 주신 이상징후 시나리오(37개)를 개발하다가 확인한 사항입니다.

**거동이 불편해 집에만 계신 분**은 지금 규칙이면 이렇게 됩니다.

- 12시간 / 24시간 / 48시간 "위치가 고정됐다" 알림이 차례로 나갑니다
- 안 움직이니 **자동 해제도 되지 않아** 모니터링 목록에 계속 남습니다
- 이런 분이 100명이면 목록이 그분들로 꽉 차서 **정작 위험한 건을 놓칩니다**

문제는 **이분들이 이 앱의 핵심 사용자(노인·1인 가구)**라는 점입니다. 지키려는 대상에게 기능이 작동하지 않습니다.

**원인**: 위치만으로는 아래 두 경우를 구분할 수 없습니다.

| 상황 | 위치 | 휴대폰이 감지한 움직임 |
|---|---|---|
| 집에서 평소처럼 지내심 | 고정 | 하루에 여러 번 걷기 감지 |
| 집에서 쓰러져 계심 | 고정 | 계속 정지 |

**제안**: 등록된 집 안에서의 위치 고정은 이상징후로 보지 않고, 대신 **"몇 시간 동안 전혀 움직이지 않았는지"**로 판정합니다. 이를 위한 움직임 감지 기능은 09-17에 이미 개발해 두었습니다.

시나리오 37개 어디에도 이 경우에 대한 예외가 없어, **원본 시나리오를 작성하신 쪽에도 확인이 필요합니다.**

## 8. 일정에 미치는 영향

| 항목 | 작업량 | 비고 |
|---|---|---|
| 전송 묶기 (1단계) | 앱 반나절 | 결정 불필요, 바로 진행 가능 |
| 머문 곳 정리 보관 (2단계) | 서버 약 1주 | **결정 필요** |
| 이상징후 규칙 보완 | 서버 2~3일 | **결정 필요** |
| 대기열 구조 | 서버 담당 협의 | 별도 |

전체 일정(안드로이드 11-27 기능 완료)에 큰 영향은 없습니다. 다만 **보관 방식은 빨리 정할수록 좋습니다.** 나중에 정하면 이미 쌓인 데이터를 다시 정리해야 합니다.
